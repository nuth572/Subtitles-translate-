Hosting KhmerSub AI

A complete guide to deploying KhmerSub AI on any platform — from one-click Vercel deploys to self-hosted Docker on your own VPS.

On this page

Overview Prerequisites 1. Vercel + Neon 2. Railway 3. Docker Compose 4. Fly.io 5. Manual VPS Environment variables Updating Troubleshooting Decision matrix

📦 What's inside the app

  • Next.js 16 with App Router and React Server Components
  • PostgreSQL via Drizzle ORM — stores translated subtitle projects
  • In-browser Whisper (transformers.js + ONNX) — speech recognition runs entirely in the user's browser, no API keys needed
  • Server-side translation proxy — forwards requests to Google Translate with fallback endpoints
  • Optional cloud Whisper (Groq / OpenAI) — enabled automatically with GROQ_API_KEY or OPENAI_API_KEY

🔑 Prerequisites

  1. A PostgreSQL database — required. Use any managed Postgres service (Neon, Supabase, Railway, Render, AWS RDS) or a local install.
  2. Node.js 20+ (only if you deploy without Docker).
  3. A DATABASE_URL environment variable pointing to your Postgres.
  4. (Optional) GROQ_API_KEY or OPENAI_API_KEY to enable cloud Whisper.

Copy .env.example to .env and fill in the values:

cp .env.example .env
# edit .env with your credentials

▲ Option 1 — Vercel + Neon

▲ Vercel Free 5 minutes

Best for quick, free, zero-ops hosting. Vercel runs Next.js natively and you pair it with a free Postgres from Neon or Supabase.

  1. Create a Postgres database on Neon (free tier, 0.5 GB) or Supabase (free tier, 500 MB). Copy the connection string (postgresql://…).
  2. Push this repo to GitHub/GitLab.
  3. Import the project on Vercel. Vercel auto-detects Next.js. In the Environment Variables section add:
    • DATABASE_URL = your Postgres connection string
    • (Optional) GROQ_API_KEY or OPENAI_API_KEY
  4. Deploy. Vercel builds and starts the app automatically.
  5. Push the schema once. Vercel doesn't run drizzle-kit push automatically, so do it from your machine: 
    # install locally first
npm install
# use the same DATABASE_URL as Vercel
export DATABASE_URL="postgresql://user:pass@host/db"
npx drizzle-kit push
  6. (Optional) Add a custom domain in Vercel → Settings → Domains.
💡 Tip Vercel has a free Neon integration — click "Add Postgres" on the Storage tab and Vercel wires DATABASE_URL for you automatically.

🚂 Option 2 — Railway

🚂 Railway One-click Managed Postgres

Best for a free managed Postgres + automatic Docker builds, with a single deploy button.

  1. Sign in to Railway with GitHub.
  2. Click New Project → Deploy from GitHub repo.
  3. Click + New → Database → Add PostgreSQL. Railway injects DATABASE_URL automatically.
  4. In your app service → Variables, make sure DATABASE_URL points at the Postgres service (Railway creates a reference variable for you).
  5. In Settings → Build the platform auto-detects Next.js.
  6. In Settings → Deploy → Custom start command, use: 
    npx drizzle-kit push && npm start
  7. Deploy. Railway builds, pushes the schema, and serves the app.
  8. Generate a domain under Settings → Networking → Public networking.

🐳 Option 3 — Docker Compose on any VPS

🐳 Docker Compose VPS $5/mo

Best for full control and cheap hosting on Hetzner, DigitalOcean, OVH, or Vultr.

Steps on your VPS

# 1. Install Docker and Compose (Ubuntu/Debian)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker

# 2. Clone the project
git clone https://github.com/yourname/khmersub-ai.git
cd khmersub-ai

# 3. Create your .env
cp .env.example .env
nano .env   # fill in GROQ_API_KEY / OPENAI_API_KEY if you want

# 4. Build and start everything (app + PostgreSQL)
docker compose up -d --build

# 5. Check logs
docker compose logs -f app

The entrypoint script automatically runs drizzle-kit push every time the app starts, so your schema is always in sync. Visit http://your-server-ip:3000.

Useful commands

ActionCommand
Rebuild after code changesdocker compose up -d --build

Put it behind HTTPS (recommended)

Add Caddy as a reverse proxy for auto-Let's Encrypt certs. Add this service to docker-compose.yml:

caddy:
  image: caddy:2-alpine
  restart: unless-stopped
  ports:
    - "80:80"
    - "443:443"
  volumes:
    - ./Caddyfile:/etc/caddy/Caddyfile
    - caddy_data:/data
  depends_on: [app]

volumes:
  pgdata:
  caddy_data:

Create a Caddyfile:

subtitles.yourdomain.com {
    reverse_proxy app:3000
}

🪁 Option 4 — Fly.io

🪁 Fly.io Global edge

Best for global edge deployment with managed Postgres.

# Install flyctl
curl -L https://fly.io/install.sh | sh
fly auth login

# Launch (creates a new app)
fly launch --no-deploy

# Add a Postgres cluster and attach it
fly postgres create --name khmersub-db
fly postgres attach khmersub-db

# (Optional) add cloud Whisper keys
fly secrets set GROQ_API_KEY=xxx

# Deploy
fly deploy

🖥️ Option 5 — Manual VPS (no Docker)

# 1. Install Node 20 + PostgreSQL 16 (Ubuntu/Debian)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs postgresql postgresql-contrib

# 2. Create the database
sudo -u postgres psql <<SQL
CREATE USER khmersub WITH PASSWORD 'choose-a-strong-password';
CREATE DATABASE khmersub OWNER khmersub;
SQL

# 3. Clone and install
git clone https://github.com/yourname/khmersub-ai.git
cd khmersub-ai
npm ci

# 4. Environment
cp .env.example .env
nano .env    # set DATABASE_URL=postgresql://khmersub:…@localhost:5432/khmersub

# 5. Push schema and build
npx drizzle-kit push
npm run build

# 6. Run with a process manager (PM2)
npm install -g pm2
pm2 start npm --name khmersub -- start
pm2 save
pm2 startup    # follow the command it prints

Put it behind Nginx + Let's Encrypt (Certbot) for HTTPS.

🔄 Updating the app

After you pull new code:

  • Vercel / Railway / Fly: just push to main — the platform rebuilds and redeploys.
  • Docker: git pull && docker compose up -d --build. The entrypoint re-pushes the schema automatically.
  • Manual VPS: 
    git pull && npm ci && npx drizzle-kit push && npm run build && pm2 restart khmersub

🛠️ Troubleshooting

"Cannot find name 'RouteContext'" type errors during build
Run npx next typegen once. The project already has generated route types.
Schema push fails
Check DATABASE_URL is correct and the Postgres server is reachable. You can run it manually with:
DATABASE_URL="…" npx drizzle-kit push
Translation returns "Sorry…" / 429
Google is rate-limiting the server IP. The app already falls back to clients5.google.com and then mymemory.translated.net. Browsers also fall back to calling Google directly, so users are rarely impacted.
Whisper is slow the first time
The speech model (75–480 MB) is downloaded once in the user's browser and cached. Subsequent visits are instant.
Large audio files crash the browser
The in-browser engine needs ~2× the decoded audio size in RAM. For files over ~30 minutes, enable the cloud engine (GROQ_API_KEY or OPENAI_API_KEY).
Docker image too big
The Dockerfile already uses Next.js standalone output, so the final image is ~200 MB.
